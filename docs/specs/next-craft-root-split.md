# Next and Craft Root Split Spec

Status: implemented

## Goal

Move the starter to a clean two-app repository layout so Turbopack only watches
the Next frontend while Craft remains available through the same root-level
developer workflow.

The split must preserve:

- independent root commands for Next and local Craft startup
- root-level environment files
- Craft DDEV startup and shutdown flow
- GraphQL schema/type generation
- CSS variable generation
- Craft Live Preview
- Craft-to-Next cache revalidation
- production build behavior
- Cloudflare Worker builds, branch previews, and production deployment from
  `main` through direct GitHub integration

## Evidence

- Code-read evidence: root `package.json` routes `bun dev` directly to the
  frontend and exposes local Craft separately as `bun dev:craft`.
- Code-read evidence: `app/next.config.ts` sets `turbopack.root` to the app
  directory.
- Code-read evidence: `craft/` is currently inside the same root as the Next
  app.
- Run evidence: `craft/vendor`, `craft/storage`, and `craft/web` together are
  about 555MB.
- Run evidence: `craft/vendor`, `craft/storage`, and `craft/web` contain about
  21k files.
- Code-read evidence: installed Next 16 config types expose `turbopack.root`,
  `turbopack.resolveAlias`, `turbopack.resolveExtensions`, `turbopack.rules`,
  `turbopack.debugIds`, and `turbopack.ignoreIssue`; they do not expose a
  Turbopack folder ignore/include watch list.
- Code-read evidence: installed Next 16 config types expose top-level
  `watchOptions.pollIntervalMs`, but no `watchOptions.ignored`.
- Code-read evidence: `src/lib/craft/client.ts` owns the cached Craft GraphQL
  fetch path and cache tags.
- Code-read evidence: `src/app/api/revalidate/route.ts` owns the Next
  revalidation endpoint.
- Code-read evidence: `src/app/api/preview/route.ts` and
  `src/lib/craft/preview.ts` own Craft preview mode.

## Non-Goals

- Do not change the Craft content model.
- Do not change GraphQL query shapes except paths required by the move.
- Do not change preview token behavior.
- Do not change cache tag names or revalidation semantics.
- Do not add dependencies.
- Do not move runtime artifacts into Git.
- Do not duplicate environment values into committed files.

## Environment Contract

Environment files stay at the repository root:

```txt
.env
.env.example
```

`app/` must not own separate source-of-truth environment files.

Root scripts must load root env files and pass the same environment to Next
commands.

Required root env groups:

```txt
# Hosted Craft runtime
CRAFT_SECURITY_KEY
CRAFT_LICENSE_KEY
PRIMARY_SITE_URL
CRAFT_DISALLOW_ROBOTS

# Hosted Craft database
CRAFT_DB_SERVER
CRAFT_DB_DATABASE
CRAFT_DB_USER
CRAFT_DB_PASSWORD

# Next public runtime
NEXT_PUBLIC_SITE_URL

# Craft GraphQL from Next
CRAFT_GRAPHQL_ENDPOINT
CRAFT_GRAPHQL_TOKEN

# Preview
CRAFT_PREVIEW_SECRET

# Revalidation
REVALIDATE_SECRET
CRAFT_REVALIDATE_URL
```

Local DDEV runtime values are generated in `craft/.ddev/.env.web`. Hosted
production defaults and asset settings are generated by the Craft
synchronization scripts.

The local GraphQL endpoint is derived from `PROJECT_NAME`:

```txt
http://<project-name>.ddev.site/gql/api
```

The local Next frontend remains:

```txt
http://localhost:3000
```

## Script Contract

Root `package.json` remains the only command surface users need.

Required commands:

```json
{
  "dev": "bun scripts/run-app.ts dev",
  "dev:craft": "bun scripts/craft-dev.ts",
  "dev:turbo": "bun scripts/run-app.ts dev",
  "dev:webpack": "bun scripts/run-app.ts dev --webpack",
  "css": "bun scripts/run-app.ts css",
  "gql": "bun scripts/run-app.ts gql",
  "gql:schema": "bun scripts/run-app.ts gql:schema",
  "gql:types": "bun scripts/run-app.ts gql:types",
  "gql:check": "bun scripts/run-app.ts gql:check",
  "build": "bun scripts/run-app.ts build",
  "cf:setup": "bun scripts/cloudflare-setup.ts",
  "cf:build": "bun scripts/run-app.ts cf:build",
  "cf:preview": "bun scripts/run-app.ts cf:preview",
  "cf:deploy": "bun scripts/run-app.ts cf:deploy",
  "cf:upload": "bun scripts/run-app.ts cf:upload",
  "cf:typegen": "bun scripts/run-app.ts cf:typegen",
  "lint": "bun scripts/run-app.ts lint && tsc -p tsconfig.scripts.json --noEmit",
  "verify": "bun run lint"
}
```

Notes:

- `dev` starts only Next from the root.
- `dev:craft` starts only local Craft through DDEV.
- `dev:webpack` remains as a diagnostic fallback.
- `css` delegates to the app-owned generator and writes into `app/src/styles`.
- `gql` runs inside `app/` because GraphQL output belongs to the frontend.
- `cf:setup` is an explicit credentialed resource step and never part of
  bootstrap, Workers Builds, release, or Craft synchronization.
- `cf:build`, `cf:preview`, `cf:deploy`, `cf:upload`, and `cf:typegen` delegate
  to the app-owned pinned OpenNext/Wrangler toolchain while still loading the
  root environment.

## Hosting Contract

Craft remains on Cyon. One OpenNext Cloudflare Worker owns the Next frontend;
R2 owns incremental cache entries, D1 owns tag revalidation state, and the
Cloudflare Images binding owns supported `/_next/image` optimization. Cloudflare
Workers Builds connects directly to GitHub, uploads preview versions for
non-production branches, and deploys production only from `main`. Workers Builds
never runs Craft synchronization or the explicit Cloudflare resource setup.
GitHub Actions independently validates lint and the OpenNext Worker build but
does not deploy either runtime.

## Dev Command Contract

`scripts/craft-dev.ts` must:

1. treat `craft/` as the Craft root
2. read root `.env`
3. sync Craft env values into `craft/.ddev/.env.web`
4. print:

```txt
[craft] Site: http://ubiq-next.ddev.site
[craft] Admin: http://ubiq-next.ddev.site/admin
[craft] GraphQL: http://ubiq-next.ddev.site/gql/api
```

## CSS Generation Contract

`app/scripts/generate-vars.ts` owns generation. Output paths are:

```txt
app/src/styles/maps.generated.scss
app/src/styles/root.generated.scss
app/src/styles/vars.generated.scss
app/src/styles/utilities.generated.scss
```

When runtime TypeScript vars are added, output path must be:

```txt
app/src/styles/vars.generated.ts
```

`bun css` must work from the root.

## GraphQL Contract

GraphQL files belong to the Next app:

```txt
app/graphql/schema.graphql
app/src/graphql-env.d.ts
app/src/queries/
```

The root `bun gql` command must run the app-local scripts with root env loaded.

Required behavior:

- schema generation uses `CRAFT_GRAPHQL_ENDPOINT`
- schema generation uses `CRAFT_GRAPHQL_TOKEN`
- output stays inside `app/`
- `gql-tada check` passes after the move

## Cache Revalidation Contract

Cache revalidation must keep the same HTTP flow:

```txt
Craft save/delete
  -> craft/modules/headless/cache_revalidation
  -> CRAFT_REVALIDATE_URL
  -> app/src/app/api/revalidate/route.ts
  -> revalidateTag(...)
```

Required checks after the move:

- Craft and Next still read the root-provided `REVALIDATE_SECRET`.
- `CRAFT_REVALIDATE_URL` points to the Next app route.
- Saving a page in Craft logs a successful revalidation response.
- Reloading the frontend after save reads updated content without manual cache
  clearing.

## Live Preview Contract

Craft preview targets remain pointed at Next:

```txt
http://localhost:3000/api/preview?uri={uri}&token={token}
```

Required checks after the move:

- `/api/preview` still enables Next Draft Mode.
- preview token is stored in the preview cookie.
- preview queries use `craftPreviewQuery()`.
- preview queries use `cache: "no-store"`.
- unsaved Craft changes appear in Live Preview.
- normal frontend requests do not use preview mode.

## Image Contract

Next image config must still allow Craft assets:

```txt
http://ubiq-next.ddev.site/**
```

Required checks after the move:

- Craft asset URLs still normalize correctly.
- `next/image` still loads Craft images in dev.
- generated Craft transforms remain reachable through DDEV.

## Root Package Strategy

Preferred root package strategy:

```json
{
  "private": true,
  "workspaces": ["app"],
  "scripts": {
    "dev": "bun scripts/run-app.ts dev",
    "dev:craft": "bun scripts/craft-dev.ts"
  }
}
```

`app/package.json` owns:

```json
{
  "scripts": {
    "css": "bun scripts/generate-vars.ts",
    "dev": "bun run css && next dev",
    "build": "bun run css && bun run gql && node node_modules/next/dist/bin/next build",
    "start": "node node_modules/next/dist/bin/next start",
    "lint": "eslint src scripts config.ts next.config.ts eslint.config.mjs",
    "gql": "bun run gql:schema && bun run gql:types && bun run gql:check"
  }
}
```

## Implementation Steps

1. Create `app/`.
2. Move frontend app files into `app/`.
3. Create or adjust root `package.json` scripts.
4. Create or adjust `app/package.json` scripts.
5. Update root scripts to use `app/` paths.
6. Update CSS generator output paths.
7. Update GraphQL generation paths.
8. Update Next config root assumptions.
9. Update README command documentation.
10. Run validation commands.

## Validation

Run from repository root:

```bash
bun css
bun gql
bun dev
```

Manual dev checks:

- open `http://localhost:3000`
- open `http://localhost:3000/sections`
- navigate between pages
- confirm the compiling indicator stops
- confirm CPU settles after route navigation
- open `http://ubiq-next.ddev.site/admin`
- open a Craft entry preview
- edit a preview field without saving and confirm the preview updates
- save a Craft page and confirm frontend normal mode updates after
  revalidation

Build checks:

```bash
bun run build
bun run lint
```

Optional diagnostic fallback:

```bash
bun run dev:webpack
```

## Rollback Boundary

This migration is path-only. Rollback is:

1. move app files back to root
2. restore root script paths
3. restore generator output paths
4. remove `app/`

Do not change Craft project config during this migration.
